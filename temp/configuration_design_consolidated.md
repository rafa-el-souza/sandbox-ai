### Plane Definitions

```
TOOLING PLANE (immutable templates, git-tracked)
└── SANDBOX_AI_HOME/          ← wherever `git clone` places the repo
    ├── .docker/              ← compose/Dockerfile templates (hidden, not user-edited)
    │   ├── compose.yml
    │   ├── core/
    │   │   ├── Dockerfile.core
    │   │   └── entrypoint.sh
    │   ├── admin/
    │   │   ├── Dockerfile.admin
    │   │   └── entrypoint.sh
    │   └── extras/
    │       ├── db-postgres.yml
    │       ├── mcp-firecrawl.yml
    │       └── Dockerfile.mcp-firecrawl
    ├── .config/              ← app config templates (hidden, not user-edited)
    │   ├── admin/            ← .zshrc, .tmux.conf, gitmux.conf, starship.toml
    │   ├── core/             ← .bashrc, .npmrc, .gitconfig, .claude.json, CLAUDE.md
    │   ├── dns-sidecar/      ← Corefile (Jinja2 template)
    │   └── proxy/            ← squid.conf (Jinja2 template), ERR_SANDBOX_403
    ├── cli/                  ← Python orchestrator source
    ├── core/                 ← Python core modules
    └── sandboxes/            ← per-instance directories

PROJECT PLANE (mutable per-instance, generated by CLI)
└── SANDBOX_AI_HOME/sandboxes/<project_name>-<project_id>/
    ├── sandbox.toml          ← instance infrastructure config (user editable)
    ├── .sandbox.env          ← instance secrets (user editable, gitignored)
    ├── docker/               ← rendered compose/Dockerfile for this instance
    │   ├── compose.yml       ← hydrated from .docker/compose.yml
    │   ├── core/
    │   │   ├── Dockerfile.core
    │   │   └── entrypoint.sh
    │   ├── admin/
    │   │   ├── Dockerfile.admin
    │   │   └── entrypoint.sh
    │   └── extras/           ← active extension overrides
    ├── config/               ← rendered app configs for this instance
    │   ├── admin/
    │   ├── core/
    │   ├── dns-sidecar/      ← rendered Corefile
    │   └── proxy/            ← rendered squid.conf, rendered allowed_domains.txt, .htpasswd
    ├── custom/config/        ← user-editable scaffold configs (sourced at end of main configs)
    │   ├── admin/            ← .zshrc, .tmux.conf overrides
    │   └── core/             ← .bashrc, .npmrc overrides
    ├── log/                  ← service log files
    │   ├── admin/            ← .zsh_history
    │   ├── core/             ← .bash_history
    │   ├── proxy/
    │   └── orchestrator/     ← orchestrator.log
    ├── cache/                ← persisted per-instance agent state
    │   └── .claude/          ← mounted to /home/agent/.claude in core container
    ├── .initialized          ← sentinel: written only after successful scaffold
    └── state.lock            ← fcntl concurrency lock for this instance (transient)

GLOBAL STATE (shared across all instances)
└── SANDBOX_AI_HOME/.state/
    ├── instances.json        ← instance registry: abs_project_dir → instance_id
    ├── ipam.json             ← global IPAM ledger (fcntl-guarded)
    └── ipam.json.lock        ← global IPAM lock file

USER PROJECT ROOT (the actual code being developed)
└── <anywhere on host fs>/    ← mounted as /workspace in core and admin containers
    └── (user's project files only — no .sandbox/ injected here)

INSTANCE DISCOVERY (on every CLI invocation)
  1. Resolve project_dir: --project-dir arg | CWD
  2. project_id  = md5(abs(project_dir))[:6]           (internal, never in sandbox.toml)
  3. project_name = basename(project_dir)               (overridable in sandbox.toml after init)
  4. Registry lookup: read SANDBOX_AI_HOME/.state/instances.json
     4a. abs_project_dir found in registry:
           instance_id  = registry[abs_project_dir]     (e.g. "myproject-8f3a9e")
           instance_dir = SANDBOX_AI_HOME/sandboxes/<instance_id>/
           → proceed to lifecycle command (start/stop/attach/destroy)
     4b. abs_project_dir NOT in registry:
           → scaffold new instance (start only; stop/attach/destroy fail with "not found")
  5. [start only] If instance_dir exists but no .initialized sentinel → re-scaffold (partial init)
```

## Schemas

### `sandbox.toml` Schema

> Per-instance config at `SANDBOX_AI_HOME/sandboxes/<project_name>-<project_id>/sandbox.toml`
> Generated at init; user-editable except where noted as IMMUTABLE.

```toml
# sandbox.toml
# Sandbox instance infrastructure configuration.
# Generated by: sandbox start (first run in project directory)

[project]
# IMMUTABLE after init: changing name requires sandbox stop --clean and manual rebind.
# The instance directory name is fixed at creation from this value.
name = "myproject"                         # auto-derived from basename(project_dir); display + COMPOSE_PROJECT_NAME
user_project_root = "/home/dev/myproject"  # absolute path to the project being developed
                                           # update via `sandbox rebind <new_path>` if project moves
host_unprivileged_user = "sandbox"         # system user owning the rootless Docker socket
host_uid = "1000"                          # host UID for container user creation (prevents bind-mount ownership drift)
warmup_prompt = ""                         # injected as claude prompt on first start; empty = no warmup

[core]
shm_size = "2gb"
pids_limit = 400
base_image = "cgr.dev/chainguard/wolfi-base:latest"  # pin digest here for reproducibility
base_distro_family = "wolfi"               # selects Dockerfile.core.<family> from template plane
git_user = ""
git_email = ""

[admin]
shm_size = "2gb"
pids_limit = 400
base_image = "debian:trixie-slim"
base_distro_family = "debian"              # selects Dockerfile.admin.<family> from template plane

[runtimes]
python = true
typescript = true
rust = true
go = false

[runtimes.node]
version = "20.12.2"
nvm_version = "0.39.7"

[components]
db_postgres = true
mcp_firecrawl = false
mcp_puppeteer = false

[components.db_postgres]
expose_host_ports = [5432]                 # host L4 bindings: 127.0.X.X:5432:5432

[components.ingress]
web_ports = [3000, 8080]                   # host L4 bindings via Caddy loopback labels

[proxy.whitelist]
# Single source of truth for egress domain allowlist.
# Rendered into allowed_domains.txt and Corefile on every start.
# To add/remove domains: edit here and run `sandbox start` (hydration overwrites rendered configs).
domains = [
  ".github.com",
  ".githubusercontent.com",
  ".api.anthropic.com",
  ".npmjs.com",
  ".npmjs.org",
  ".pypi.org",
  ".pythonhosted.org",
  ".crates.io",
  ".rust-lang.org",
  ".golang.org",
  ".go.dev",
  ".debian.org",
  ".ubuntu.com"
]
```

### `.sandbox.env` Schema

> Per-instance secrets at `SANDBOX_AI_HOME/sandboxes/<project_name>-<project_id>/.sandbox.env`
> Never committed to source control. Created with mode 0600 (owner-read-only).
> Contents are conditional on enabled [components] in sandbox.toml.
> Populated interactively via getpass() on first start (interactive TTY) or pre-populated manually (CI/non-TTY).

```env
# .sandbox.env — STRICTLY UNTRACKED SECRETS

# ── Core Container ────────────────────────────────────────────────────────────
CORE_ANTHROPIC_API_KEY=""     # REQUIRED — Anthropic API key for the agent (claude)
CORE_GITHUB_TOKEN=""          # optional  — GitHub personal access token; leave empty to skip

# ── Database (present only when [components] db_postgres = true) ──────────────
PG_USER="agent"               # REQUIRED — postgres superuser inside the container
PG_PASSWORD=""                # REQUIRED — postgres password
PG_DB="sandbox_db"            # REQUIRED — database name

# ── MCP: Firecrawl (present only when [components] mcp_firecrawl = true) ─────
FIRECRAWL_API_KEY=""          # REQUIRED — Firecrawl service API key
```

### `sandbox start` Sequence

```
PRE-CONDITIONS: dev user invokes CLI; --project-dir or CWD used as project_dir

── PHASE 0: INSTANCE RESOLUTION ───────────────────────────────────────────────

1. Resolve project_dir
   abs_project_dir = abs(--project-dir | CWD)

2. Compute identity
   project_id   = md5(abs_project_dir)[:6]
   project_name = basename(abs_project_dir)  [override: sandbox.toml [project] name if exists]

3. Registry lookup
   Read SANDBOX_AI_HOME/.state/instances.json
   If abs_project_dir in registry:
     instance_id  = registry[abs_project_dir]     (e.g. "myproject-8f3a9e")
     instance_dir = SANDBOX_AI_HOME/sandboxes/<instance_id>/
     → skip to PHASE 1
   Else: → SCAFFOLD SUB-SEQUENCE

── SCAFFOLD SUB-SEQUENCE (first run only) ──────────────────────────────────────

S1. Create directory tree (all owned by dev):
      sandboxes/<id>/docker/core/
      sandboxes/<id>/docker/admin/
      sandboxes/<id>/docker/extras/
      sandboxes/<id>/config/admin/
      sandboxes/<id>/config/core/
      sandboxes/<id>/config/dns-sidecar/
      sandboxes/<id>/config/proxy/
      sandboxes/<id>/log/admin/
      sandboxes/<id>/log/core/
      sandboxes/<id>/log/proxy/
      sandboxes/<id>/log/orchestrator/
      sandboxes/<id>/cache/.claude/
      sandboxes/<id>/custom/config/admin/
      sandboxes/<id>/custom/config/core/

S2. Write sandbox.toml with defaults
    (name, user_project_root, host_unprivileged_user, host_uid auto-detected, etc.)

S3. Create .sandbox.env with mode 0600 via os.open(O_WRONLY|O_CREAT|O_EXCL, 0o600)
    Write component-conditional secret stubs (empty values)

S4. Set default ACLs for dev on log/cache dirs (D-39):
    setfacl -d -m u:dev:rwx  sandboxes/<id>/log/
    setfacl -d -m u:dev:rwx  sandboxes/<id>/cache/

S5. Register in .state/instances.json:
    { abs_project_dir: instance_id }

S6. Secret prompting:
    If interactive TTY:
      For each required secret (driven by enabled [components] in sandbox.toml):
        value = getpass.getpass("<SECRET_NAME> (<description>): ")
      Write all collected secrets to .sandbox.env
    Else (no TTY):
      Fail: "Sandbox initialized. Populate .sandbox.env at <path> and rerun."
      Exit 1

S7. Write .initialized sentinel
    → Continue to PRE-LOCK CHECK

── PRE-LOCK: WARM STATE CHECK ──────────────────────────────────────────────────

[Applies only to existing instances — scaffold path has no running containers]

1. Read sandbox.toml (name, host_unprivileged_user) — available from instance_dir

2. Check if containers already running (no locks held):
   sudo machinectl shell <host_unprivileged_user>@.host -- /bin/bash -c \
     "COMPOSE_PROJECT_NAME=<name> docker compose -f <instance_dir>/docker/compose.yml ps -q"

   If output non-empty:
     "Sandbox '<name>' is already running. Use 'sandbox attach' to reconnect."
     exit 1  [no locks to release — clean fast exit]

── PHASE 1: LOCKING ────────────────────────────────────────────────────────────

1. Acquire state.lock (fcntl LOCK_EX | LOCK_NB on sandboxes/<id>/state.lock)
   Failure → "Another sandbox start is already in progress for this instance."

2. Acquire global IPAM lock (fcntl LOCK_EX | LOCK_NB on .state/ipam.json.lock)

── PHASE 2: IPAM ALLOCATION ────────────────────────────────────────────────────

1. Read .state/ipam.json ledger
   If project_id in ledger: base_index = ledger[project_id]  [idempotent re-start]
   Else: allocate lowest available base_index (0–13311)
         Check: 100 + (base_index * 3) // 256 > 255 → raise IPAMExhaustedError
         Write ledger[project_id] = base_index

2. Derive subnets (g = base_index * 3):
   ISOLATED_NET = 10.(100 + g//256).(g%256).0/24
   PROXY_NET    = 10.(100 + (g+1)//256).((g+1)%256).0/24
   EGRESS_NET   = 10.(100 + (g+2)//256).((g+2)%256).0/24

3. Derive static IPs from module constants:
   DNS_SIDECAR_IP         = ISOLATED_NET base + .53
   DB_POSTGRES_IP         = ISOLATED_NET base + .54
   MCP_FIRECRAWL_ISOLATED = ISOLATED_NET base + .55
   AGENT_ISOLATED_IP      = ISOLATED_NET base + .3
   ADMIN_ISOLATED_IP      = ISOLATED_NET base + .2
   PROXY_IP               = PROXY_NET base + .254
   AGENT_PROXY_IP         = PROXY_NET base + .3
   ADMIN_PROXY_IP         = PROXY_NET base + .2

4. Release IPAM lock (state.lock remains held)

── PHASE 3: CREDENTIAL GENERATION ─────────────────────────────────────────────

1. Generate proxy credentials (cold start only):
   password = generate_random_password()   # 32-char, secrets module
   htpasswd_hash = generate_proxy_hash(password)  # bcrypt
   Write sandboxes/<id>/config/proxy/.htpasswd:
     "proxyuser:<htpasswd_hash>"
   Store password in memory for compose env injection as SANDBOX_PROXY_PASSWORD

── PHASE 4: HYDRATION ──────────────────────────────────────────────────────────

Build Jinja2 context from: Pydantic-parsed sandbox.toml + IPAM values + proxy credentials

Render templates (.docker/ → sandboxes/<id>/docker/):
  Dockerfile.core.<base_distro_family>  → docker/core/Dockerfile.core
  .docker/core/entrypoint.sh            → docker/core/entrypoint.sh
  Dockerfile.admin.<base_distro_family> → docker/admin/Dockerfile.admin
  .docker/admin/entrypoint.sh           → docker/admin/entrypoint.sh
  .docker/compose.yml                   → docker/compose.yml
  [if db_postgres]   extras/db-postgres.yml    → docker/extras/db-postgres.yml
  [if mcp_firecrawl] extras/mcp-firecrawl.yml  → docker/extras/mcp-firecrawl.yml
                     Dockerfile.mcp-firecrawl  → docker/extras/Dockerfile.mcp-firecrawl

Render templates (.config/ → sandboxes/<id>/config/):
  dns-sidecar/Corefile  → config/dns-sidecar/Corefile      [domains from proxy.whitelist]
  proxy/squid.conf      → config/proxy/squid.conf           [isolated_net subnet]
  Generate:  config/proxy/allowed_domains.txt               [domains from proxy.whitelist]
  Generate:  config/proxy/trusted_clients.acl               [ISOLATED_NET, PROXY_NET CIDRs]
  Copy:      proxy/ERR_SANDBOX_403                          → config/proxy/ERR_SANDBOX_403
  Copy:      admin/{.zshrc,.tmux.conf,gitmux.conf,starship.toml}  → config/admin/
  Copy:      core/{.bashrc,.npmrc,.gitconfig,.claude.json,CLAUDE.md} → config/core/

── PHASE 5: ACL GRANTS ─────────────────────────────────────────────────────────

Run as dev (no sudo):
  setfacl -R -m u:<host_unprivileged_user>:rX  sandboxes/<id>/docker/
  setfacl -R -m u:<host_unprivileged_user>:rX  sandboxes/<id>/config/
  setfacl -d -m u:dev:rwx  <user_project_root>     [idempotent; D-39]

── PHASE 6: LAUNCH ─────────────────────────────────────────────────────────────

Build compose file list:
  files = ["-f sandboxes/<id>/docker/compose.yml"]
  [if db_postgres]   files += ["-f sandboxes/<id>/docker/extras/db-postgres.yml"]
  [if mcp_firecrawl] files += ["-f sandboxes/<id>/docker/extras/mcp-firecrawl.yml"]

1. docker compose up (non-interactive, blocking until healthy, via machinectl):
   sudo machinectl shell <host_unprivileged_user>@.host -- /bin/bash -c \
     "COMPOSE_PROJECT_NAME=<name> docker compose <files> up -d --build --wait"
   [--wait blocks until all services with healthchecks report healthy; requires Compose v2.1+]
   On timeout/failure: emit service health summary, release state.lock, exit 1

── PHASE 7: HANDOVER ───────────────────────────────────────────────────────────

1. Release state.lock

2. Drop user into admin container (interactive PTY, via machinectl):
   If warmup_prompt is set in sandbox.toml:
     sudo machinectl shell <host_unprivileged_user>@.host \
       /usr/bin/docker exec -e SANDBOX_WARMUP_PROMPT="<warmup_prompt>" -it <name>-admin-1 zsh
   Else:
     sudo machinectl shell <host_unprivileged_user>@.host \
       /usr/bin/docker exec -it <name>-admin-1 zsh
   [Note: no `-- /bin/bash -c` — PTY is allocated through machinectl directly]
   [SANDBOX_WARMUP_PROMPT passed at exec time; admin .zshrc reads it on shell init
    and launches: claude -p "$SANDBOX_WARMUP_PROMPT" --dangerously-skip-permissions]
   Terminal is now owned by the admin container session.
```

### `sandbox attach` Sequence

```
PRE-CONDITIONS: instance resolved via registry; containers assumed running

1. Read sandbox.toml (name, host_unprivileged_user)

2. Verify containers are running:
   sudo machinectl shell <host_unprivileged_user>@.host -- /bin/bash -c \
     "COMPOSE_PROJECT_NAME=<name> docker compose -f <instance>/docker/compose.yml ps -q"
   If no output: "Sandbox '<name>' is not running. Use 'sandbox start' to launch."

3. Drop user into admin container (interactive PTY):
   sudo machinectl shell <host_unprivileged_user>@.host \
     /usr/bin/docker exec -it <name>-admin-1 zsh
   [No hydration, no credential regeneration, no lock acquisition]
```

### `sandbox destroy` Sequence

```
PRE-CONDITIONS: instance resolved via registry; this operation is irreversible

── PHASE 0: CONFIRMATION ───────────────────────────────────────────────────────

1. Read sandbox.toml (name, host_unprivileged_user, user_project_root)

2. Safety confirmation:
   If --force flag: skip prompt
   Else (interactive):
     Print: "WARNING: This permanently deletes sandbox '<name>' and all its state."
     Print: "         Named volumes (Postgres data, MCP IPC) will be unrecoverable."
     Print: "         Your project at <user_project_root> is NOT affected."
     Prompt: "Type the sandbox name to confirm: "
     Input ≠ name → abort silently, exit 0

── PHASE 1: LOCKING ────────────────────────────────────────────────────────────

1. Acquire state.lock (fcntl LOCK_EX | LOCK_NB on sandboxes/<id>/state.lock)
   Failure → "Cannot destroy: another operation is in progress for this instance."
   [Lock is held via open fd; file will be deleted by rmtree later — safe, fd-based]

── PHASE 2: CONTAINER AND VOLUME TEARDOWN ──────────────────────────────────────

Build compose file list (same as start, from sandbox.toml [components]):
  files = ["-f sandboxes/<id>/docker/compose.yml"]
  [if db_postgres]   files += ["-f sandboxes/<id>/docker/extras/db-postgres.yml"]
  [if mcp_firecrawl] files += ["-f sandboxes/<id>/docker/extras/mcp-firecrawl.yml"]

1. docker compose down -v (unconditional — handles warm and cold state equally):
   sudo machinectl shell <host_unprivileged_user>@.host -- /bin/bash -c \
     "COMPOSE_PROJECT_NAME=<name> docker compose <files> down -v"
   Removes: containers (if running), networks, ALL named volumes
   [Idempotent: if containers already stopped, still removes volumes and networks cleanly]

2. [Optional] Remove locally-built images (only if --prune-images flag):
   sudo machinectl shell <host_unprivileged_user>@.host -- /bin/bash -c \
     "docker image rm <name>-core <name>-admin 2>/dev/null || true"

── PHASE 3: ACL REVOCATION ─────────────────────────────────────────────────────

Run as dev (no sudo):
  setfacl -R -x u:<host_unprivileged_user>  sandboxes/<id>/docker/
  setfacl -R -x u:<host_unprivileged_user>  sandboxes/<id>/config/
  [ACLs on user_project_root, log/, cache/ are NOT revoked — dev's permanent access to dev's dirs]

── PHASE 4: STATE CLEANUP ──────────────────────────────────────────────────────

1. Acquire global IPAM lock (fcntl LOCK_EX on .state/ipam.json.lock)
   Read .state/ipam.json
   Remove entry: del ledger[project_id]
   Write .state/ipam.json (base_index slot is now free for reuse)
   Release IPAM lock

2. Read .state/instances.json
   Remove entry: del registry[abs_project_dir]
   Write .state/instances.json
   [Guarded by state.lock still held from Phase 1]

── PHASE 5: DIRECTORY REMOVAL ──────────────────────────────────────────────────

Safety check:
  Assert instance_dir starts with SANDBOX_AI_HOME/sandboxes/
  [Guards against registry corruption pointing at arbitrary path]

shutil.rmtree(instance_dir)
  Removes: all rendered configs, compose files, logs, cache, secrets, sentinel, state.lock file
  Does NOT touch: user_project_root (the user's actual project — never owned by sandbox)

Close state.lock fd
  [File already deleted by rmtree; closing fd releases the lock — no dangling lock]

── PHASE 6: LOG ────────────────────────────────────────────────────────────────

"Sandbox '<name>' permanently destroyed. IPAM slot freed for reuse."
```

### ACL Permission Model

Two distinct access patterns govern the filesystem ACL lifecycle:

**Pattern A — `sandbox` user reads compose/config files directly** (to execute `docker compose`)
**Pattern B — container subUIDs read/write workspace, logs, cache** (rootless Docker user namespace remapping)

```
HOST FILESYSTEM: WHO ACCESSES WHAT
──────────────────────────────────────────────────────────────
Directory / File                       Accessor           How
──────────────────────────────────────────────────────────────
sandboxes/<id>/docker/                 sandbox (UID 1001)  direct read (ACL rX)
sandboxes/<id>/config/                 sandbox (UID 1001)  direct read (ACL rX)

user_project_root/                     dev (UID 1000)      owner (always)
user_project_root/                     container agent     subUID ~100999 (rootless remap)
  → dev reads container-created files via default ACL (set once at scaffold)

sandboxes/<id>/log/                    dev (UID 1000)      default ACL (set at scaffold)
sandboxes/<id>/log/                    container agent     creates files as subUID (dir mount)

sandboxes/<id>/cache/                  dev (UID 1000)      default ACL (set at scaffold)
sandboxes/<id>/cache/                  container agent     creates files as subUID (dir mount)

sandboxes/<id>/config/ (rendered)      containers          bind-mounted RO — no ACL needed
```

```
ACL LIFECYCLE OPERATIONS
──────────────────────────────────────────────────────────────
SCAFFOLD or START (run as dev):
  setfacl -d -m u:dev:rwx  <user_project_root>     # default: dev reads subUID-created files
  setfacl -d -m u:dev:rwx  sandboxes/<id>/log/     # default: dev reads container log files
  setfacl -d -m u:dev:rwx  sandboxes/<id>/cache/   # default: dev reads container cache files
  (never revoked; idempotent on every start — safe to run repeatedly)

HYDRATE / START (run as dev, before docker compose up):
  setfacl -R -m u:sandbox:rX  sandboxes/<id>/docker/   # sandbox reads compose files
  setfacl -R -m u:sandbox:rX  sandboxes/<id>/config/   # sandbox reads rendered configs
  (revoked on stop)

STOP (run as dev, after docker compose down confirms):
  setfacl -R -x u:sandbox  sandboxes/<id>/docker/      # revoke compose file access
  setfacl -R -x u:sandbox  sandboxes/<id>/config/      # revoke config file access
  (no workspace/log/cache revocation — sandbox never had explicit ACL there)
```

### `sandbox stop` Sequence

```
PRE-CONDITIONS: instance resolved via registry; sandbox.toml read

1. Warm-state check
   sudo machinectl shell sandbox@.host -- /bin/bash -c \
     "COMPOSE_PROJECT_NAME=<name> docker compose -f <instance>/docker/compose.yml ps -q"
   → no output (no running containers): warn + exit 0
   → output non-empty (containers running): continue

2. Container shutdown (blocking, via machinectl)
   sudo machinectl shell sandbox@.host -- /bin/bash -c \
     "COMPOSE_PROJECT_NAME=<name> docker compose -f <instance>/docker/compose.yml down"
   Removes: containers, networks
   Preserves: named volumes (db-postgres-data, ipc vols)
   Blocks until all containers confirm exit

   [if --clean flag]:
   ... docker compose -f <instance>/docker/compose.yml down -v
   Removes: containers, networks, ALL named volumes (data loss — logged clearly)

3. ACL revocation (run as dev, no sudo)
   setfacl -R -x u:<host_unprivileged_user>  sandboxes/<id>/docker/
   setfacl -R -x u:<host_unprivileged_user>  sandboxes/<id>/config/

4. Log output
   → "Sandbox '<name>' stopped. Named volumes preserved."
   → "Sandbox '<name>' stopped. Named volumes destroyed — Postgres data unrecoverable." [--clean]
```

## Decisions

| # | Decision | Rationale |
|---|---|---|
| D-01 | `SANDBOX_AI_HOME` = directory of `git clone` (not `~/.sandbox/`) | Eliminates confusion between install dir and state dir; makes the repo self-contained |
| D-02 | Template plane uses hidden dirs `.docker/` and `.config/` inside `SANDBOX_AI_HOME` | Prevents accidental user edits; clear visual distinction from generated/instance files |
| D-03 | Per-instance directories at `SANDBOX_AI_HOME/sandboxes/<project_name>-<project_id>/` | Enables full multi-instance segregation |
| D-04 | `/workspace` mount comes from `USER_PROJECT_ROOT` (wherever the user's project is on the host) | Keeps user project clean — no `.sandbox/` injected into their repo |
| D-05 | `.zsh_history` → `sandboxes/<id>/log/admin/`, `.bash_history` → `sandboxes/<id>/log/core/` | Telemetry scoped to instance, not polluting user project root |
| D-06 | Claude cache (`~/.claude/`) → `sandboxes/<id>/cache/.claude/` | Per-instance agent state; prevents cross-contamination between sandboxes |
| D-07 | Global IPAM ledger at `SANDBOX_AI_HOME/.state/ipam.json` | Single source of truth for subnet allocation across all instances on the host |
| D-08 | IPAM allocates a triple of consecutive `/24` subnets per instance; ledger stores `project_id → base_index` (integer); subnets derived as `10.(100+g//256).(g%256).0/24` where `g = base_index*3`, `g+1`, `g+2` for isolated, proxy, egress | Supports 13,312 concurrent instances (vs 156 with `/16`); deterministic derivation; no wasted address space |
| D-09 | `dns-sidecar` is the canonical name for the DNS component | Matches Docker service name; eliminates the 4-name inconsistency (`config/dns-sidecar/`, `[dns-sidecar]` in toml, service `dns-sidecar`) |
| D-10 | `allowed_domains.txt` is a rendered artifact (generated from `sandbox.toml` whitelist), always mounted RO | Single source of truth in toml; no hand-edited static file in template plane; regenerated on each start |
| D-11 | One instance per directory; CWD (or `--project-dir`) is the instance locator | Acceptable constraint for v1; workaround via symlink/sibling dir if two configs needed for same codebase |
| D-12 | `project_name` auto-derived from `basename(project_dir)`; overridable in `sandbox.toml` | Human-readable instance dirs with hash uniqueness guarantee |
| D-13 | `project_id` = first 6 chars of `md5(abs(project_dir))`; internal only, not in `sandbox.toml` | Auto-derived at discovery time; user never sees or sets this |
| D-14 | Instance lookup uses `SANDBOX_AI_HOME/.state/instances.json` registry; directory name is stable, not re-derived on each lookup | Fixes project-move problem: `sandbox rebind` updates registry key + `user_project_root` without renaming dir |
| D-15 | Implicit init: `sandbox start` scaffolds on first run; prompts for secrets interactively via `getpass()` in-process (no rerun needed) | Single invocation UX; secrets never appear in shell history or on screen; `.initialized` sentinel prevents partial-scaffold reuse |
| D-16 | `--project-dir` flag overrides CWD for both instance discovery and workspace mount | Enables scripting and non-CWD invocation |
| D-17 | `[network.topology]` removed from `sandbox.toml`; octets are Python module constants | Subnet variation serves collision prevention (functional), not security; IPAM /16 allocation provides the actual per-instance uniqueness |
| D-18 | Infra sidecars (`proxy`, `dns-sidecar`) resource limits (`shm_size`, `pids_limit`) not user-configurable | Unnecessary surface area; locked to sane defaults in template |
| D-19 | Privilege boundary: `sudo machinectl shell sandbox@.host -- /bin/bash -c "..."` | `sandbox` user owns rootless Docker socket; dev user types sudo password per command; no machinectl container binding needed |
| D-20 | Hydration cycle: Pydantic model parses `sandbox.toml` → typed context → Jinja2 renders templates into `sandboxes/<id>/` | Clean separation: validation (Pydantic) + rendering (Jinja2) |
| D-21 | `.state/instances.json` registry maps `abs(project_dir)` → `instance_id`; `sandbox rebind <new_path>` updates both registry and `user_project_root` in toml | Authoritative lookup; directory name is stable human-readable label, not a recomputed key |
| D-22 | `.sandbox.env` created with `os.open(O_WRONLY\|O_CREAT\|O_EXCL, 0o600)` before any content is written | Prevents race window between file creation and permission setting; owner-read-only from birth |
| D-23 | In non-interactive contexts (no TTY), missing secrets cause immediate fail with path to `.sandbox.env`; interactive contexts use `getpass()` prompts | Supports both human and CI invocation patterns |
| D-24 | Teardown semantics: `stop` = containers only; `stop --clean` = containers + named volumes; `destroy` = full instance dir + registry + IPAM ledger cleanup | Clear operational vs structural command boundary; `.initialized` only removed on `destroy` |
| D-25 | Rendered instance configs (`sandboxes/<id>/config/`) are always regenerable; hydration overwrites them on every `start` | Precious state: `sandbox.toml`, `.sandbox.env`, `custom/config/`, `cache/`, `log/` — never overwritten by hydration |
| D-26 | `base_image` + `base_distro_family` in `sandbox.toml` for `[core]` and `[admin]`; hydration selects correct Dockerfile template variant | User never edits Dockerfiles; pinning = change `base_image` only; distro switch = change both fields |
| D-27 | Template plane ships Dockerfile variants per distro family: `Dockerfile.core.wolfi` (default), `Dockerfile.admin.debian` (default); additional families added as separate files | Extensible without changing hydration logic; switch distro = add a template file |
| D-28 | `warmup_prompt` moves from `[core]` to `[project]` level in `sandbox.toml` | Semantic: warmup is a project-level concern (what task this sandbox starts with), not a core container spec |
| D-29 | `.sandbox.env` secret naming: `CONTAINER_` prefix dropped; service-prefixed (`CORE_*`, `PG_*`, `FIRECRAWL_*`) | `CONTAINER_` conveyed nothing; service prefix makes consumer explicit |
| D-30 | `.sandbox.env` contents are conditional on enabled components in `sandbox.toml`; hydration only writes secrets blocks for enabled components | No dead env vars; `PG_*` block absent when `db_postgres = false` |
| D-31 | `.htpasswd` regenerated on cold start only (containers not running); credential preserved across warm re-entries | Avoids squid/proxy mismatch when containers are already up; `squid -k reconfigure` complexity deferred |
| D-32 | `sandbox attach` command needed (separate from `start`); bypasses hydration, no credential regeneration, drops user into admin container shell | `start` and `attach` have distinct semantics: initialize+launch vs reconnect-to-running |
| D-33 | `host_uid` moved from per-service to `[project]` level | Both core and admin write to the same `/workspace` bind mount; they must share the same host UID |
| D-34 | `[project] name` field is IMMUTABLE after init; changing it requires `sandbox stop --clean` + manual rebind | `name` drives `COMPOSE_PROJECT_NAME`; changing it mid-lifecycle orphans existing containers under the old project name |
| D-35 | `[components.db_postgres]` and `[components.ingress]` sub-tables under `[components]` (replaces top-level `[database]` and `[ingress]`) | Better semantic grouping; component config lives next to component toggle |
| D-36 | `[proxy.whitelist]` stays as a TOML sub-table; no `[proxy]` parent section required | Clean TOML; no infra sidecar resource knobs leaked back in |
| D-37 | `CORE_GITHUB_API_KEY` renamed to `CORE_GITHUB_TOKEN` | Aligns with GitHub's own naming convention for personal access tokens |
| D-38 | `sandbox` user is granted ACL read access (`rX`) on `sandboxes/<id>/docker/` and `sandboxes/<id>/config/` at hydration time; revoked (`-x u:sandbox`) at stop | These are the only dirs `sandbox` reads directly (to run docker compose); workspace/log/cache are accessed by container subUIDs, not by sandbox |
| D-39 | `dev` user is granted default ACL (`-d -m u:dev:rwx`) on `user_project_root`, `sandboxes/<id>/log/`, and `sandboxes/<id>/cache/` at scaffold time; never revoked | Default ACL ensures dev can read any files created by container subUIDs; these ACLs are permanent (dev's own access to dev's own dirs) |
| D-40 | Log/history bind mounts use DIRECTORY mounts, not file mounts | File-level bind mounts pre-created by `dev` appear as owned by `nobody` inside rootless container; directory mounts let the container create the file, default ACL gives dev read access |
| D-41 | `HISTFILE` env var configured in container zshrc/bashrc to point to a path inside the mounted log directory | Enables history persistence via directory mount without hardcoding the file path in compose |
| D-42 | `core/ipam.py` rewritten: allocates lowest available `base_index` (0–13311); ledger maps `project_id → base_index`; subnets derived at runtime, not stored | Enables slot reuse after `destroy`; converts lifetime cap to concurrent cap |
| D-43 | `core/ipam.py` overflow detection: `100 + (base_index * 3) // 256 > 255` raises `IPAMExhaustedError` with actionable message pointing to `sandbox destroy` | Current overflow produces invalid IP → opaque Docker error with no IPAM context |
| D-44 | `sandbox destroy` removes the entry from both `instances.json` AND `ipam.json` to free the base_index slot for reuse | Without ledger cleanup, destroy only removes the instance dir; the IPAM slot stays consumed permanently |
| D-45 | `state.lock` is transient: acquired at start of `start` sequence, released when containers are confirmed up and tmux handover completes; `stop` does not interact with it | Prevents concurrent `start` executions on the same instance; no persistent held-lock during runtime |
| D-46 | `sandbox destroy` requires explicit name-confirmation prompt or `--force` flag | Irreversible operation; name-typing confirmation prevents accidental invocation |
| D-47 | `sandbox destroy` runs `docker compose down -v` unconditionally regardless of container state | Idempotent: removes volumes and networks whether containers are running or already stopped; avoids warm/cold branching logic |
| D-48 | `sandbox destroy` removes: named volumes, compose ACL grants, IPAM ledger entry, registry entry, entire instance directory; does NOT touch `user_project_root` | The user's project is independent of the sandbox instance; only sandbox-managed state is removed |
| D-49 | Docker images built for the instance not removed by default; `--prune-images` flag enables optional cleanup | Images are safe to leave (they're just disk); most re-starts benefit from cached layers; explicit opt-in for full cleanup |
| D-50 | `instance_dir` path verified to have prefix `SANDBOX_AI_HOME/sandboxes/` before `shutil.rmtree` | Guards against registry corruption or path traversal producing a malformed path pointing outside the sandboxes directory |
| D-51 | Lock sequence for destroy: acquire `state.lock` (fd) → do all work → `rmtree(instance_dir)` (deletes lock file from disk) → close fd (releases lock); no explicit unlock before rmtree needed | fcntl locks are fd-associated; deleting the file does not release the held fd lock; safe to rmtree while holding |
| D-52 | Warm state check in `sandbox start` is performed PRE-LOCK (after instance resolution, before acquiring `state.lock` or IPAM lock) | If already running, fail fast with zero lock contention; acquires no resources that need cleanup |
